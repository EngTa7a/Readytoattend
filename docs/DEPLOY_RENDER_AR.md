# نشر جاهز على Render — دليل عملي

## ما الذي ستنشره؟
- خدمة Node.js API بخطة Standard (1 CPU / 2 GB RAM).
- PostgreSQL مُدارة بخطة Basic-1gb و5 GB تخزين.
- اتصال قاعدة البيانات عبر عنوان داخلي.
- ترحيل قاعدة البيانات قبل كل نشر.
- فحص صحة عبر `/health`.
- سر JWT يتم توليده من المنصة.
- CORS يجب ضبطه على عنوان الواجهة الفعلي.

## قبل البدء
1. أنشئ حساباً على GitHub وحساباً على Render.
2. ارفع محتويات هذا المشروع إلى مستودع GitHub خاص. لا ترفع ملف `.env` أو أي أسرار.
3. تأكد أن `render.yaml` في جذر المستودع.
4. في Render اختر New → Blueprint ثم اربط مستودع GitHub.
5. راجع الموارد والتكلفة التي تعرضها المنصة قبل التأكيد، لأن الأسعار والخطط قد تتغير حسب المنطقة.
6. أنشئ الخدمات. سيطلب Render قيمة `CORS_ORIGINS` لأننا تركناها سرّاً غير مضبوط عمداً. في مرحلة الاختبار، ضع عنوان الواجهة الفعلي؛ لا تستخدم `*` في الإنتاج.

## بعد النشر
1. افتح خدمة API ثم Logs، وتأكد من نجاح البناء والترحيل وظهور رسالة الاستماع.
2. افتح `https://YOUR-SERVICE.onrender.com/health`. يجب أن ترى JSON فيه `status: ok` و`database: ok`.
3. افتح Shell للخدمة إن كانت متاحة في خطتك، وشغّل `npm run create-admin`. أنشئ اسم مستخدم وكلمة مرور قوية بطول 12 حرفاً أو أكثر. إذا لم توفر المنصة Shell، شغّل الأمر محلياً بعد إعداد `DATABASE_URL` المؤقت بشكل آمن، ولا تضع بيانات الاتصال في مستودع Git.
4. سجّل الدخول عبر `POST /api/v1/auth/login` باستخدام Postman، ثم اختبر `/api/v1/me`.
5. أضف فرعاً بإحداثياته الفعلية، ثم أضف موظفاً تجريبياً. لا تستخدم بيانات موظفين حقيقية حتى إتمام مراجعة الأمن والخصوصية.
6. احفظ `DATABASE_URL` داخلياً فقط في متغيرات البيئة. لا تفتح PostgreSQL للإنترنت ولا تشارك سلسلة الاتصال.
7. أنشئ نسخة احتياطية واختبر استعادتها إلى قاعدة منفصلة قبل إدخال بيانات فعلية.

## إعداد CORS
بعد نشر الواجهة، اجعل `CORS_ORIGINS` قائمة عناوين دقيقة مفصولة بفواصل، مثلاً:
`https://attendance.example.com,https://admin.example.com`
لا تضع عنوان API نفسه إلا إذا كانت الواجهة تُقدَّم منه.

## إعدادات النسخ الاحتياطي
- قاعدة البيانات المدفوعة على Render تدعم النسخ/الاستعادة بحسب الخطة؛ خطط Hobby توفر نافذة PITR أقصر من Pro.
- فعّل تصديراً منطقياً يومياً إلى مخزن منفصل خارج قاعدة البيانات، مع تشفير وتقييد الوصول.
- احتفظ بنسخ أسبوعية/شهرية حسب سياسة المؤسسة، واختبر الاستعادة دورياً.
- لا تعتبر وجود النسخ التلقائية وحده خطة تعافٍ كاملة.

## تنبيه قبل الإنتاج
هذه الحزمة بداية خادم، وليست بعد نظاماً إنتاجياً مكتملًا. قبل تشغيلها للموظفين:
- ربط واجهة النسخة الثالثة بالخادم وIndexedDB/SQLite لطابور offline.
- إكمال إدارة حسابات المستخدمين وصلاحيات كل فرع.
- إضافة رفع الصور إلى مخزن خاص وتوقيع روابط الرفع؛ `photoObjectKey` وحده ليس رفعاً لصورة.
- إضافة قواعد تسلسل الحضور والانصراف، والتعامل مع الساعة غير الصحيحة، والتقارير اليومية/الشهرية.
- اختبارات أمنية واختبارات ضغط تشمل الذروة، ومراجعة حماية البيانات.
- وضع سياسة احتفاظ وحذف للصور وسجلات الحضور.
